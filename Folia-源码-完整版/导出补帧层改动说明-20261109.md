# 导出补帧层改动说明（2026-11-09）

> 承接《渲染画面可以用 RIFE 或 IFRNet 补帧吗》的结论：**不在实时渲染画面上补帧，只接「录屏导出」这一条帧流**。
> 本轮实现了接口兼容 RIFE / IFRNet 的可插拔后端、完整降级链、用户开关与调度互斥。
> **未重新打包** exe / apk / 源码 zip。

---

## 一、一句话结论

按上一轮第 ①–⑤ 步全部落地。补帧层是一套**独立、默认关闭、可整体摘除**的模块，只挂在 `videoExportFramePipeline.ts` 的 `TransformStream` 上；28 个可视化引擎、3 套 pass 链、4 个独立 document **一行都没动**。

| 做了 | 没做 |
|---|---|
| 与模型无关的 `FrameInterpolator` 接口（RIFE / IFRNet 都兼容） | 没有把 20MB 权重打进安装包 |
| ONNX Runtime Web 后端（动态加载，可选依赖） | 没有硬装 `onnxruntime-web`，构建零新增依赖 |
| 帧混合降级后端 + 转场保护 + 超时跳过 | 没有在运行时同时跑两个模型 |
| 延迟一帧的帧配对与 timestamp 插值 | 没有改实时渲染循环、没有加 pass |
| 主设置页开关 + 三语文案 | 没有改远程导出面板（跨窗口 localStorage 不共享） |
| microRender 自适应降帧互斥 | 没有改 Android 侧（WebView 无可用 WebGPU 推理通道） |

## 二、架构分层

```
getDisplayMedia 抓屏
   ↓  MediaStreamTrackProcessor
planPresetFrame → 零拷贝 visibleRect / cover 缩放      ← 原逻辑，一字未改语义
   ↓  normalizeFrame()（新抽出，返回预设尺寸 VideoFrame）
createInterpolationStage()                             ← 新增，唯一接入点
   ├─ 帧配对（延迟一帧输出）
   ├─ 能力探测 / 预热实测（capabilities.ts）
   ├─ 后端：ONNX(RIFE|IFRNet) → 帧混合 → 直接放行
   ├─ 转场保护 / 单对帧超时 / 连续失败永久降级
   └─ exportGuard（导出期间冻结 microRender 降档）
   ↓  MediaStreamTrackGenerator → MediaRecorder → 文件
```

| 文件 | 职责 |
|---|---|
| `frameInterpolation/types.ts` | `FrameInterpolator` 契约、`OnnxModelSpec`（把两模型差异收进配置）、默认设置 |
| `frameInterpolation/frameMath.ts` | 纯函数：中间帧时间戳、duration、32 倍数对齐、MAD 场景差异、`chooseBackend` 降级决策 |
| `frameInterpolation/blendInterpolator.ts` | 零依赖帧混合后端 + 32×18 缩略图差异采样 |
| `frameInterpolation/onnxInterpolator.ts` | RIFE/IFRNet 共用 ORT-Web 后端：动态 import、IndexedDB 权重缓存、NCHW 预处理、padding、输出回 `VideoFrame` |
| `frameInterpolation/capabilities.ts` | 工厂：能力探测 → 预热实测（按面积折算 + 1.5 安全系数）→ 定后端，8 秒初始化超时 |
| `frameInterpolation/stage.ts` | 帧流 stage：延迟一帧、超时跳过、连续 3 次失败降级、guard 持有/释放 |
| `frameInterpolation/exportGuard.ts` | 模块级引用计数，供调度器读取 |
| `useFrameInterpolationStore.ts` | 设置 + `readFrameInterpolationSettings()`（不依赖 React 树） |

## 三、六个关键设计决策

**① 为什么只接导出链路**：`videoExportFramePipeline.ts` 已有 `TransformStream<VideoFrame, VideoFrame>`，帧带完整 `timestamp`、音频轨直通，是最自然的插帧点。而实时主画面补帧会「先主动丢帧、再花算力补回来」，与 `frameRateLimiter` 和 microRender 调度器方向完全对冲。

**② 为什么要延迟一帧**：生成 t=0.5 的中间帧必须同时拿到 t=0 和 t=1。stage 始终缓存一帧，最终输出 `f1, mid12, f2, mid23, f3 …`，时间戳严格递增；`flush()` 补出最后一帧。导出场景延迟 16.7ms 完全可接受，实时画面不可接受。

**③ 降级链与预算口径**：
`WebGPU/ORT-Web → WebGL EP → WASM → 帧混合 → 不补帧`。ORT 内部选前三档，本层只看**预热实测是否跑得进预算**。
`frameBudgetUs` 定义为**整对帧总预算**（默认 16 000 µs ≈ 一个帧间隔）；倍率越高单帧可分越少（4× 时要求单帧 ≤ 1/3 预算）。工厂与 stage 用同一口径，避免 4× 时悄悄背压。

**④ 绝不阻塞实时录制**：这条管线是**实时抓屏 + 实时 MediaRecorder 编码**，不是录完再离线处理。所以：初始化最多等 8 秒、单对帧超时立即跳过、连续 3 次失败永久降级到帧混合、ORT 不可取消的后台推理不再被取回。

**⑤ 接口兼容 ≠ 同时跑两个模型**：RIFE 与 IFRNet 输入契约一致（2 帧 RGB → 1 帧），差异只在 `OnnxModelSpec`（`dual` / `concat`、`timestepName`、`inputScale`、`paddingMultiple`）。切换模型只改这份配置，**只有一套推理代码**。默认 `auto` 选 RIFE（迭代最活跃、生态最全）。

**⑥ 开关放主设置页，不放远程导出面板**：导出在**主窗口**执行，`RemoteVideoExportPanel` 在远程控制窗口，两者 localStorage 不共享。放在「图形 → 性能」可完全避开跨窗口同步。

## 五、如何真正启用 RIFE / IFRNet

默认没有权重 URL，工厂会自动走**帧混合**后端（功能可见、无鬼影以外的代价）。要跑神经模型：

```bash
# ① 安装可选运行时（不装也能构建、也能用帧混合）
npm i onnxruntime-web

# ② 开发者工具 Console 配置权重地址（同源或允许 CORS 的 URL）
localStorage.setItem('folia.exportInterpolation.modelUrl', '/models/rife_v4.onnx')
localStorage.setItem('folia.exportInterpolation.enabled', 'true')
# 可选：'rife' | 'ifrnet' | 'auto'，倍率 2 | 4
localStorage.setItem('folia.exportInterpolation.model', 'rife')
```

其余可用键：`multiplier`、`allowBlendFallback`、`frameBudgetUs`、`sceneChangeThreshold`（前缀均为 `folia.exportInterpolation.`）。权重首次 fetch 后缓存进 IndexedDB `folia-frame-interpolation/models`。

模型导出需满足：输入为 `img0` / `img1` 两路 NCHW fp32（0..1）、可选 `timestep`、输出名 `output`、H/W 按 32 对齐。若你的导出是 concat6 或 0..255 值域，改 `OnnxModelSpec` 即可，不用动推理代码。

## 七、已知限制与真机验证清单

**沙箱无 GUI / 无 WebGPU / 无真实权重，以下均未实测：**

1. **背压**：ORT 推理无法取消，超时后后台仍占 GPU。已用「超时跳过 + 永久降级」缓解，但 1080p/4K + 4× 在集显上大概率全程降级到帧混合。建议先用 2×、720p 试。
2. **预热折算**：用 128×72 小图按面积线性折算并乘 1.5 安全系数，是保守估算，不等于真实分辨率耗时。
3. **内容适配**：可视化粒子/闪烁/硬切是光流模型弱项，已加 MAD 场景差异阈值（默认 52）跳过；阈值可能需按实际画面调。
4. **duration**：中间帧给了均分后的 `duration`，但最终帧率由 `timestamp` 与编码器决定，需真机确认输出 fps。
5. **Android**：Capacitor WebView 无可靠 WebGPU 推理通道，本层在安卓上只会走帧混合或直接放行。
6. **`dist/`** 现在停在 **Electron/PWA 版**（含 `sw.js`）。打 APK 前必须重跑 `npm run cap:sync:android`。

**上机自测 5 条**：① 开关关闭时导出视频与旧版逐帧一致；② 开启 + 无权重时得到帧混合、录制不卡；③ 配权重后 RIFE 生效、切 IFRNet 不报错；④ 导出过程中帧率档位不跳（互斥生效）；⑤ 人为制造场景切换，中间帧不「融化」。
