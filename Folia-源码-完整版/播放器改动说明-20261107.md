## 一、动手前的三处复核修正

| 原建议 | 核实结果 | 本轮处理 |
|---|---|---|
| **P0-2「本地歌曲没有进原生播放链」** | **不成立**。`playbackFiles.ts:67-85` 的 `playableUrlForNativeRef()` 在安卓本地曲库返回 `http://127.0.0.1:<port>/audio/<ref>`，`nativePlaybackEngine.supports()` 放行 http，本来就交给 ExoPlayer。只有「回环服务探测被挡」的异常兜底才取成 blob，以及桌面 File System Access 读进来的文件。`useNativePlaybackRuntime.ts:57` 那句注释是早期实现的遗留描述 | **不改运行时逻辑**，只修正两处过期注释 |
| **P0-1「自动混音在 Android 能开、开了无效」** | **程度需下调**。`useAppFoundation.ts:228-231` 启动时会把 `crossfadeEnabled / crossfadeMs / crossfadeCurve` 推给原生，由 `FoliaNativePlayer.crossfadeTo` 执行 —— 开关**有效**。真实问题是「同一个开关在桌面是节拍对齐 + 分轨自动混音，在安卓只是交叉淡化」，且设置页注释还写着「AutoMix 那组开关已经删掉」，与代码不符 | 改为**能力表 + 平台语义说明 + 注释修正**，不灰置开关（灰掉会误伤有效的原生交叉淡化） |
| **P0-3「桌面端缺系统级媒体控制」** | 需补正：项目**已有**完整的自定义全局快捷键系统（`globalShortcutRules.ts` / `useGlobalShortcuts.ts`，Ctrl+Alt+Shift+字母绑定播放命令），缺的只是键盘 / 耳机上的**标准媒体键**（MediaPlayPause 等）与 Windows SMTC | 只补 3 个标准媒体键，复用现有 `thumbar-action` IPC，不新建体系 |

顺带确认「拔耳机暂停」「Android 原生 DSP」「交叉淡化两端都有」等结论仍成立（见原建议文档附录），未重复改动。

### 2.1 平台能力表与设置说明

`playbackCapabilities.ts` 用 `isAndroidAppShell()`（不依赖 Capacitor 桥就绪，与 `KaraokeRow` 同一套纪律）判断能力，`hasElectronBridge()` 判断桌面。设置页每次渲染重新问、不缓存快照。

安卓上「过渡」开关现在会显示：**「安卓为原生交叉淡化：开关、时长与曲线由播放器直接执行；按节拍对齐、可分轨的自动混音仅桌面端可用。」** 开关本身保持可点，因为它确实驱动原生 `crossfadeTo`。

### 2.2 桌面标准媒体键

`electron/main.cjs` 新增 `registerMediaKeys()` / `unregisterMediaKeys()`：

| 键 | 动作 | 去向 |
|---|---|---|
| `MediaPlayPause` | `play-pause` | `sendThumbarAction()` → `thumbar-action` IPC |
| `MediaNextTrack` | `next` | 同上 |
| `MediaPreviousTrack` | `previous` | 同上 |

- 复用渲染层 `useElectronPlaybackBridge.ts:392-419` 已有的订阅，没有新增 IPC 通道或 preload 接口。
- **不注册 `MediaStop`**：渲染层没有对应动作，发过去会被当成 play-pause 的 toggle，把「停止」变成「暂停 / 继续」。
- macOS 跳过（媒体键由系统媒体会话接管，Electron 的 `globalShortcut` 抢不到）；注册失败只打 warn，不影响启动。
- 与现有 `globalShortcuts.cjs` 的 `Ctrl+Alt+Shift+字母` 不冲突，后者 `dispose()` 只注销自己注册的键。
- **Windows SMTC / 音量面板 / 锁屏控制仍未接**（需要原生模块），本轮只解决键盘与耳机按键。

### 2.3 断点续播

两条链分别处理，因为原生播放器没有 `loadedmetadata` 事件：

| 链路 | 恢复时 | 消费点 |
|---|---|---|
| Web `<audio>`（桌面 / 网页） | `pendingResumeTimeRef.current = savedPositionSec` | `AppSurface.tsx:290-298` 的 `onLoadedMetadata`，会按 `duration - 0.25` 夹住 |
| 原生 ExoPlayer（安卓） | `nativePlaybackEngine.setPendingStartPosition(sec)` | `setSource()` → `nativePlayer.prepare({ startPositionMs })` → `FoliaNativePlayerPlugin.kt:508-516` → `FoliaNativePlayer.kt:296` 的 `seekTo()` |

已核实的完整参数链：`nativePlayerPlugin.ts:180` 定义 → Kotlin 插件读取 → 原生 prepare 里 `seekTo(startPositionMs)`。这条协议原本就存在，只是 Web 侧从未传过非零值。

**写入侧的约束**

- 5 秒节流 + 页面隐藏 / `pagehide` 时补一帧并立即落盘（后台 JS 定时器会被系统挂起，不能只靠 interval）。
- 位置来源：原生由 `nativePlaybackEngine.getPositionSec()` 直接问引擎，Web 用 `currentTime.get()`；`ownsPlayback()` 在桌面恒 false，不会误用。
- 自动混音过渡冻结（`transitionDisplay`）期间不写，避免把落点记到错误的歌上。
- 按 `songKey` 匹配，超过 7 天不恢复，播放器清空时由 `forgetPlaybackCache()` 一起清掉。
- **只在会话恢复时读**：用户主动重新点同一首歌不经过恢复流程，仍从头开始。
- 原生服务仍在播的分支（`adoptNativePlaybackState`）在上面就 return，不会被磁盘上的旧快照顶掉更准的位置。
- 恢复后仍保持暂停（沿用原有 `shouldAutoPlayRef` 语义），不自动出声。
