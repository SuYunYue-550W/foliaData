### QQ 20279：对上一轮诊断的**重要更正**

上一轮我建议「在 `reportsDeviceLimit()` 加一条 message 文本正则兜底」——**这个方案不够，需要更正**。复查发现更根本的原因：

- `src/nativeBridge/api/folia.js:871/878-884`（Android 本地桥 `login_qr_check`）**完全不透传** `upstreamCode` / `upstreamErrorKey` / `failureHint` / `primaryFailure`；终态错误返回的是 **`code: 0` + message + failureStage**。
- `qqProvider.ts:787` 只在 `code === 800` 时进 800 分支并调用 `isQqDeviceLimit()`；**`code:0` 直接落到 `:831` 通用 `qqCheckFailure`** → 判定函数压根没被调用。
- 同一缺失导致 `wrong-scan-app`、`account-banned`、`account-restricted`、`account-binding`、`rate-limited`、`primaryFailure` **全部在 Android 网页版被误归类成通用「平台拒绝 / 请稍后重试」**，专门的中文处置文案永远用不上；`console.warn('qr-check:upstream-rejected')` 也不打印，排错线索丢失。
- `docs/qq-music-deployment.md:314` 说「3.3.0 起 primaryFailure 网页版也能认出来」，那是针对 serverless/桌面内嵌 qq-music-api，**对 Android 本地桥不成立**（文档与实现偏差）。

→ 正确修法有两个层次：① **桥层**让 `folia.js` 透传 `upstreamCode` 并产出 `failureHint`/`primaryFailure`；② **客户端层**把 `code:0` 终态错误也纳入 800 分支的判定路径，并补不依赖 `window.electron` 的 20279 兜底。**根治账号登录仍靠清设备**，代码只改善提示。
