## 0. 结论速览（先说最反直觉的三点）

1. **论「整个应用」的功能总量，电脑端远多于手机端，不是反过来。** Electron 侧有约 125 个 IPC 桥接、31 类事件订阅，覆盖窗口/托盘/全局快捷键/ffmpeg/MNN/视频导出/Discord/本地 HTTP 服务/标签写回等；手机端只有 56 个插件方法。手机端强在「音频与系统 UI」，电脑端强在「能碰操作系统」。
2. **论「桌宠鲸鱼」这一项，要分两层看：**
   - 论**系统级显示能力**：电脑端确实差 —— 桌宠只是应用内 `position:fixed` DOM 覆盖层，切到别的应用就看不见；手机端是 `TYPE_APPLICATION_OVERLAY` 系统悬浮窗，能浮在任何应用之上。
   - 论**交互丰富度**：电脑端反而**更多** —— 漫游、双击彩蛋、拖动换动作、弹窗避让、播放/暂停舞蹈联动、开屏 CSS morph 过渡全都完整；最新手机端这些全被禁用或弱化（详见 §2.2）。
3. **最容易被忽略、也最实际的一条：电脑端 exe 是 11 月 4 日的旧构建，手机端 apk 是 11 月 5 日 20:41 的最新版，差约 25 小时、跨 4 代 apk 迭代。** 11/5 的所有改动一份都没进 exe。

## 2. 桌宠鲸鱼专项对比（本轮改动核心）

### 2.1 架构差异

| 维度 | 电脑端（Electron） | 手机端（Android 最新） |
|---|---|---|
| 渲染载体 | 主 WebView 内 `<div class="whale-pet">`，`position:fixed; z-index:2147483646` | 独立 WebView 加载 `file:///android_asset/whale-float.html` |
| 窗口类型 | 应用内部 DOM 层 | `TYPE_APPLICATION_OVERLAY` 系统悬浮窗 + 前台服务 |
| 跨应用可见 | **否**，只在 Folia 窗口内 | **是**，浮在任何应用之上 |
| 鲸鱼数量 | 1（主 WebView DOM） | 1（主 WebView 用 CSS guard 隐藏，浮层为唯一渲染源） |
| 位置控制 | `pet.js` 的 `_setPos` 写 CSS transform + localStorage | `WindowManager` 改窗口 x/y + SharedPreferences `whale_float` |
| 尺寸控制 | `--pet-size` CSS 变量 | 窗口宽高（dp），`whale-float.html` 用 `100vw/100vh !important` 铺满 |
| 开屏→落位过渡 | `splash.ts` CSS morph + `pet.takeOver()` 双缓冲切换视频 | `ValueAnimator` 连续插值窗口 x/y/width/height，同一只鲸鱼几何变换 |
| 交互事件源 | DOM `pointerdown/move/up` + `dblclick` | 原生 `FrameLayout.onTouch` + `Choreographer` 逐帧 `updateViewLayout` |
| 交互开关 | `interactive:true`（默认） | `interactive:false`、`persistence:false`（`whale-float.html:71-73`） |
| 保活 | 无（应用关掉就没了） | `START_STICKY` 前台服务 + 常驻通知 `NOTIF_ID=90210` |
| 原生代码 | **零**（`electron/` 下无任何 whale/pet 文件） | `FloatingWhaleService.kt` + `FoliaNativePlugin.kt` 10 个插件方法 + Manifest 服务/权限 |

> 两端 `pet.js` **字节完全一致**（md5 `6e53efbfc8bbd5dd2a2dddc25634281a`），95 个 webm 动作资源也同源。差异全部来自构造参数、宿主窗口、调用链，不来自动画内容。

### 2.5 手机端浮层的已知限制

- 漫游留白、双击彩蛋缺失、拖动换动作/弹窗避让/触边反弹/朝向镜像失效（见 §2.2）。
- **播放状态 `react` 联动未接线** —— 设置页 note 承诺「播放音乐时跳舞，暂停时安静待机」在浮层不成立，只剩空闲随机动作 + 鼓点缩放脉冲。
- 联动跑在主 WebView，主 App 退后台/被杀后停摆，而浮层仍常驻显示，存在结构性错位。
- 无 `BOOT_COMPLETED` 接收器：**设备重启后浮层不会自动出现**，必须再开一次 App；`START_STICKY` 只覆盖服务被回收重建。
- 服务被回收重建且 Intent 为 null 时，size/opacity 等设置回退默认值 `SIZE_DP=168`。
- 无悬浮窗权限或 13+ 无通知权限时浮层起不来；部分 ROM 无授权设置项，`openOverlaySettings` 静默失败。
- 两套位置存储互不互通，仅首启单向种子继承；`window.alpha` 恒 1f；`.whale-pet` 被 `!important` 强制铺满视口。
- 逐帧改窗口几何会让 WebView 重测视口，是方案唯一重开销点（靠整数去重缓解）；`setWebContentsDebuggingEnabled(true)` 在发布包里也开着。
- O 以下退回 `TYPE_PHONE`；常驻通知不可关闭。

## 5. 「电脑端差了什么」的准确清单

### A. 结构性差距（Android 原生专属，电脑端架构上不存在）

1. **跨应用系统悬浮窗桌宠** —— 电脑端桌宠只在 Folia 窗口内 `z-index` 置顶，切走就看不见。手机端能浮在微信、桌面、任何应用之上。
2. **前台服务常驻 + 常驻通知保活** —— 手机端关掉 App 主界面鲸鱼还在；电脑端关窗口就没了。
3. **开屏→落位的窗口几何连续过渡** —— 手机端用 `ValueAnimator` 对同一只鲸鱼插值 x/y/w/h；电脑端是「CSS morph + 双 video `takeOver`」两条渲染路径拼接。
4. **系统级权限体系**（悬浮窗授权、通知权限、前台服务权限）与授权引导页。
5. **原生级拖拽**（`WindowManager` + `Choreographer` 逐帧）与 `SharedPreferences` 位置持久化。
6. **服务复用 / 冷启动重放开屏 / 单实例 / 旋转重夹取** 这些原生生命周期治理。

### B. 版本差距（可补，且是眼下最实际的一条）

7. **exe 停在 11-04 19:58（或 22:15），比最新 apk 早约 22–25 小时**，不含 11/5 的 4 代 apk 迭代与 20:33–20:40 的最后一轮重写。
8. **11/5 对 Web 层的重写没进 exe**：`src/whalePet/floating.ts`（新增）、`init.ts`、`splash.ts`、`pet.js`、`index.tsx` 的健壮性改动（浮层代理、竞态治理、开屏链重写、去重优化）桌面端一份都没有。
9. **文档滞后**：`改动说明.md`、两个源码 zip、完整交付包全部停在 11-04，不含 `floating.ts` / `FloatingWhaleService.kt` / `whale-float.html`，无法据以复现 11/5 版本。

### C. 反向说明：电脑端「不差」反而「更强」的部分

10. 桌宠交互：漫游、漫游速度、触边反弹、朝向镜像、双击彩蛋、拖动换动作、弹窗自动避让、永远置顶开关、播放/暂停舞蹈联动、reduced-motion 全链路降级、快速拖动渲染降级、松手弹性过渡 —— **电脑端全有，手机端全失效或弱化**。
11. 应用能力：§4 整张表的几十项 Electron 独占能力，手机端一个都没有。

## 6. 如果要补齐电脑端，可行路径（好消息：底层已经有了）

Electron 侧**已经具备做系统级置顶桌宠所需的全部窗口能力，只是没用在桌宠上**：

| 已有能力 | 位置 | 用途 |
|---|---|---|
| `setMainWindowAlwaysOnTop` / 托盘「窗口置顶」 | `main.cjs:2419, :2114` | 创建独立 `BrowserWindow` 并 `setAlwaysOnTop(true, 'screen-saver')` |
| `setMainWindowClickThroughEnabled` / 托盘「点击穿透」 | `main.cjs:2420, :2113` | 让鲸鱼区域之外不吞鼠标 |
| 透明窗口模式 | `preload.cjs:199` `get/setWindowTransparentMode` | 窗口背景透明，只显示鲸鱼 |
| 壁纸窗口控制器 | `electron/wallpaper/windowsWallpaperController.cjs` | 已有「窗口沉到桌面层」的完整实现可复用 |
| `isWindowAlwaysOnTopSupported` | `windowAlwaysOnTopSupport.cjs` | Windows 下恒 true（仅 Linux 原生 Wayland 不可用） |
| 远程控制第二窗口 | `main.cjs:7302-7472` | 可参考「额外 BrowserWindow + 快照桥」的现成范式 |

最小方案：新建一个 `transparent + frame:false + alwaysOnTop + skipTaskbar` 的 `BrowserWindow` 加载 `whale-float.html`（复用手机端那份资源），用 IPC 同步设置与位置，主窗口保留设置页。这样电脑端即可获得与手机端等价的「跨应用置顶、单一渲染源、窗口几何过渡」，同时保留桌面端更完整的交互（漫游/双击彩蛋/弹窗避让）。**但这需要重新构建 exe，且必须先用 `ELECTRON_DEV=false ELECTRON=true npx vite build` 重打 dist**（当前 `dist/` 停留的是 Capacitor 版）。
